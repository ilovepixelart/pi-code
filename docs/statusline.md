# Statusline

Runs a configured Claude `statusLine` command. Source: [`extensions/status-line.ts`](../extensions/status-line.ts).

- The stdin JSON follows Claude's contract, with two fields it no longer lists (`hook_event_name`, sent as `Status`, and `permission_mode`) kept for scripts written against the older shape, and several it now lists that pi has no source for (`workspace.git_worktree`, `workspace.repo.*`, `worktree.*`, `pr.*`, `prompt_id`, `agent.name`, `vim.mode`): `version`, `hook_event_name`, `session_name`, a `cost` block with wall and API durations and lines added/removed, a `context_window` token breakdown, `exceeds_200k_tokens`, `workspace.added_dirs` (always empty: pi has no /add-dir), `effort` in Claude's vocabulary (pi's `minimal` maps to `low`, `off` omits it), and `rate_limits` carrying the `five_hour`/`seven_day` utilization with `resets_at` as Unix epoch seconds; an expired window is dropped rather than left stale. `fast_mode`, `prompt_cache`, and `spend_limit` have no pi source and stay absent.
- Scripts run with `CLAUDECODE=1`, `CLAUDE_CODE_CHILD_SESSION=1`, and `COLUMNS`/`LINES` set to the terminal dimensions.
- `padding` and `refreshInterval` are honored, with a 300ms debounce. Re-run triggers follow Claude, minus the two pi cannot source (a vim-mode toggle, and a warm prompt cache reaching its expiry): turns, each assistant message, compaction, permission-mode changes, a rate-limit window reaching `resets_at`, and mid-session settings edits (file watcher); a new trigger cancels an in-flight script. A managed-settings `statusLine` wins over the files, and `allowManagedHooksOnly` narrows the setting to managed entirely.
- Without a configured command, a built-in statusline shows turn state and session cost.
